# 대리총무 구현 계획서

> 기준 문서: [문제정의서.md](문제정의서.md) (웹사이트 판). 이 계획서는 그 문서의 기능·개인정보·합격선을 실제로 만들 단위로 나눈 것이다.

## 1. 목표와 범위

**만들 것**　총무가 휴대폰 브라우저에서 정산 대화를 붙여넣으면, 근거가 붙은 정산표를 만들고 결과 링크로 공유하는 웹사이트.

**완성의 정의**
- 문제정의서 4장 예시(가람·보람·다온·라온)를 붙여넣으면 1원까지 같은 정산표와 송금안이 나온다.
- 애매한 정정은 질문으로 막고, 답하기 전에는 발행되지 않는다.
- 모임원은 가입 없이 결과 링크에서 자기 몫과 이유를 본다. 결과 페이지에는 원 발언이 없다.
- 원문은 마지막 수정 7일 뒤, 결과 링크는 확정 30일 뒤 자동 삭제된다.

**만들지 않는 것 (후속 범위)**　카카오톡 직접 연동, 실제 송금, 자동 독촉, 영수증 인식, 외화·선입금·부분 환불·공동결제 자동 계산, 회원 가입.

## 2. 전체 구조

```
[휴대폰 브라우저]                         [웹사이트 서버]                      [외부]
행사 만들기 ─────────────────────────▶ 행사·토큰 발급
붙여넣기 → 가림(이름→별칭, 번호 가림) ─▶ 규칙 파서 → AI 추출 ───────────▶ CLOVA Studio (HCX-007)
검토 화면 ◀───── 초안·질문 ──────────── 조건 정리기
질문 답·직접 입력 ─────────────────────▶ 조건 정리기 → 계산기
확정·발행 ─────────────────────────────▶ 판 관리 → 저장소(TTL)
                                         결과 페이지 ◀────────────── 모임원
```

원칙 세 가지
1. **실명·전화·계좌는 브라우저 밖으로 나가지 않는다.** 가림은 전송 전에 브라우저에서 한다.
2. **AI는 '사건 후보'만 낸다.** 무엇이 최종 조건인지는 조건 정리기(규칙 코드)가, 금액은 계산기(정수 코드)가 정한다.
3. **모든 확정값에는 근거 줄 번호나 총무 확인 이력이 붙는다.**

## 3. 화면

| # | 화면 | 주소 | 하는 일 |
| --- | --- | --- | --- |
| S1 | 행사 만들기 | `/` | 행사 이름, 참여자 명단(순서 고정)과 별칭 입력. 만들면 관리 링크 안내. |
| S2 | 붙여넣기 | `/m/{관리토큰}/paste` | 사전 고지·동의(AI 제공사, 국외 이전 여부, 보관 기간). 원문 붙여넣기 → 화자 이름을 명단에 연결 → 가림 미리보기 → 전송. |
| S3 | 검토 | `/m/{관리토큰}` | 줄 번호 붙은 발언을 ‘확정 후보 / 확인 필요 / 정산 외’로 표시. 질문 카드, 직접 항목 추가, ‘AI 추출 초안’ 표시. |
| S4 | 정산표 | `/m/{관리토큰}/table` | 사람별 순결제액·부담·잔액. 금액을 누르면 항목·참여자·원 발언·정정 발언·총무 확인값. |
| S5 | 확정·발행 | `/m/{관리토큰}/publish` | “이전에 공유하거나 송금한 사람이 있나요?” 없음/있음/모름. 판 번호, 변동액, 문구 복사. ‘모두 지우기’. |
| S6 | 결과 페이지 | `/r/{결과토큰}` | 읽기 전용. 별칭·항목·금액·버전만. 이름을 누르면 항목별 계산 이유. 검색 노출 차단. |

### S2 가림 규칙 (브라우저)

| 대상 | 방법 |
| --- | --- |
| 화자 이름 | 붙여넣은 원문에서 화자 목록을 뽑아 총무가 명단의 별칭에 연결. 연결한 이름은 본문에서도 별칭으로 치환. 연결 안 된 화자는 전송 전 경고. |
| 전화번호 | `01[016789]-?\d{3,4}-?\d{4}` → `[전화번호]` |
| 계좌번호 | 하이픈 포함 숫자 묶음 `\d{2,6}-\d{2,6}-\d{2,8}` 등 → `[계좌번호]` |
| 사적 발언 | 총무가 줄 단위로 체크해 제외 |

지원할 붙여넣기 형식: 카카오톡 모바일(`[이름] [오후 9:12] 내용`), PC 내보내기(`2026. 11. 19. 오후 9:12, 이름 : 내용`). 형식을 못 읽으면 줄마다 화자를 직접 고르게 한다.

## 4. 서버 모듈

### 4-1. 규칙 파서 `parse`

- 입력: 가린 줄 목록. 출력: 줄마다 `{no, speaker, amounts[]}`.
- 금액 인식: `52,001원`, `52001원`, `4만 8천 원`, `4만8천`, `3.5만` 등 → 원 단위 정수.
- 확실한 것만 읽는다. 의미 해석은 하지 않는다.

### 4-2. AI 추출 `extract`

- 입력: 가린 줄 목록 + 명단(별칭) + 파서 결과. 출력: **사건 목록(JSON)**, 형식은 6장.
- 네이버 CLOVA Studio의 **HCX-007** 모델과 구조화 출력(`responseFormat: {type: "json", schema}`)을 쓴다. 구조화 출력은 HCX-007에서만 되고, 추론(Thinking)·함수 호출과 함께 쓸 수 없으므로 추론은 끈다.
- 스키마는 타입·필수값·enum 위주로 단순하게 쓴다(`pattern` 등 일부 키워드 미지원). 응답은 서버에서 같은 스키마로 한 번 더 검사한다.
- 입력 데이터의 학습 사용 여부와 보관 기간은 CLOVA Studio 이용 약관·정책으로 확인하고, 결과를 S2 사전 고지 문구에 반영한다.
- 근거 줄 번호가 없거나 존재하지 않는 줄을 가리키는 사건은 버린다.
- 10초 안에 응답이 없거나 형식이 틀리면 실패 처리 → S3에서 직접 입력으로 전환.
- 요청·응답 본문은 운영 로그에 남기지 않는다. 모델·프롬프트 버전은 사건 목록과 함께 저장한다.

### 4-3. 조건 정리기 `resolve` (핵심)

사건을 줄 번호 순서로 적용해 항목 목록·질문 목록·차단 사유를 만든다.

| 사건 | 처리 |
| --- | --- |
| 결제 | 항목 생성. 결제자 1명, 금액 > 0, 분담자 1명 이상. |
| 정정 | 대상이 하나로 정해지면 해당 값을 바꾸고 근거를 잇는다. 후보가 둘 이상이면 질문 `Q-대상`(“어느 결제 금액을 바꿀까요?”). |
| 제외 | “술 안 마셨어”처럼 분리 금액이 없으면 질문 `Q-분리`(제외 항목과 금액). 분리 후 합이 원 결제액과 같아야 한다. |
| 환불 | 상태 ‘완료’ + 전액이면 원 결제와 묶어 순액 0원. ‘취소 예정’이면 질문 `Q-환불`로 보류. 부분 환불은 범위 밖. |
| 중복 의심 | 같은 결제자·비슷한 금액·같은 항목이 두 번이면 질문 `Q-중복`. |
| 범위 밖 | 외화·선입금·부분 환불·공동결제 → ‘수동 정산’ 표시, 전체 송금안 발행 차단. |
| 정산 외 | 항목을 만들지 않는다. 총무가 수동 항목으로 바꿀 수 있다. |

**발행 가능 조건**　미해결 질문 0건, 범위 밖 0건, 모든 항목이 위 결제 조건 충족.

총무의 답과 직접 입력은 `확인값`으로 저장하고 `확인자: 총무`를 근거로 남긴다. 확인값은 AI 사건보다 우선한다.

### 4-4. 계산기 `calc`

1. 항목마다 `몫 = 금액 ÷ 분담자 수`(정수 나눗셈), `나머지 = 금액 mod 분담자 수`.
2. 나머지는 분담자를 **명단 순서**로 정렬해 앞에서부터 1원씩 더한다. 받은 사람을 기록한다.
3. 순결제액 = 환불 반영 결제액 합. 잔액 = 순결제액 − 총부담. 양수는 받을 돈, 음수는 보낼 돈.
4. 송금안: 보낼 사람 목록과 받을 사람 목록을 각각 명단 순서로 두고, 앞에서부터 `min(보낼 돈, 받을 돈)`씩 짝짓는다.
5. 검산(실패 시 발행 차단): 항목별 부담 합 = 항목 금액, 전체 부담 합 = 전체 순결제액, 잔액 합 = 0, 송금 반영 후 모두 0.

### 4-5. 판 관리 `version`

- 발행할 때마다 판 번호 +1. 판에는 항목·부담·잔액·송금안·발행 시각·이전 공유 여부를 저장.
- 2판부터 문구 첫 줄: `[N−1판을 대체하는 N판]`, 사람별 변동액 표 포함.
- 이전 공유 여부가 ‘있음’ 또는 ‘모름’이면 송금안을 빼고 변동액 표만 낸다.
- 결과 링크 주소는 그대로 두고 최신 판을 보여준다.

## 5. 서버 API

| 메서드·경로 | 권한 | 내용 |
| --- | --- | --- |
| `POST /api/events` | 없음 | 행사 생성. `{eventId, adminToken, resultToken}` 반환 |
| `POST /api/events/{id}/excerpt` | 관리 토큰 | 가린 줄 저장 → parse → extract → resolve. 초안 반환 |
| `GET /api/events/{id}/draft` | 관리 토큰 | 현재 초안·질문·정산표 |
| `POST /api/events/{id}/answers` | 관리 토큰 | 질문 답, 직접 입력 항목, 줄 분류 수정 → resolve·calc 재실행 |
| `POST /api/events/{id}/publish` | 관리 토큰 | `{priorShared: "없음"|"있음"|"모름"}` → 새 판, 문구 반환 |
| `GET /api/r/{resultToken}` | 결과 토큰 | 결과 페이지 데이터(별칭·항목·금액·버전만) |
| `DELETE /api/events/{id}` | 관리 토큰 | 모두 지우기(원문·근거·판·결과 즉시 삭제) |

토큰은 128비트 이상 무작위 값(base64url). 관리 토큰은 요청 헤더로만 보내고 로그에 남기지 않는다.

## 6. 데이터 형식

### 사건 (AI 추출 출력)

```json
{
  "events": [
    {"type": "payment",  "id": "P1", "line": "01", "payer": "가람", "amount": 52001, "item": "저녁", "split": ["가람","보람","다온","라온"]},
    {"type": "correct",  "line": "03", "target": "P1", "set": {"amount": 48001}},
    {"type": "exclude",  "line": "07", "who": "라온", "target": "P1", "what": "주류", "amount": null},
    {"type": "refund",   "line": "06", "target": "P3", "status": "done", "full": true},
    {"type": "cancel_planned", "line": "08", "target": "P3"},
    {"type": "out_of_scope", "line": "09", "reason": "foreign_currency"},
    {"type": "not_settlement", "line": "05"}
  ]
}
```

`target`이 확실하지 않으면 AI는 후보를 배열로 낸다(`"target": ["P1","P2"]`). 조건 정리기는 후보가 둘 이상이면 질문을 만든다.

### 저장소 (Cloud DB for Cache, 키별 TTL)

| 키 | 내용 | 보관 |
| --- | --- | --- |
| `event:{id}` | 행사 이름, 명단 순서, 토큰 해시, 생성·수정 시각 | 결과와 같이 |
| `excerpt:{id}` | 가린 줄 목록 (**암호화**) | 마지막 수정 후 7일 |
| `extract:{id}` | 사건 목록, 모델·프롬프트 버전 | 마지막 수정 후 7일 |
| `confirm:{id}` | 질문 답, 직접 입력, 줄 분류 수정 | 마지막 수정 후 7일 |
| `version:{id}:{n}` | 판별 정산 결과 (원 발언 없음) | 확정 후 30일 |

원문 계열 키는 백업 대상에서 뺀다. 수정할 때마다 7일 TTL을 다시 건다.

## 7. 기술 선택과 인프라 (네이버 클라우드)

### 기술 선택

| 영역 | 선택 | 이유 |
| --- | --- | --- |
| 화면·서버 | Next.js + TypeScript 한 프로젝트, Docker 컨테이너 1개 | 화면과 API를 한 번에 배포 |
| 실행 환경 | 네이버 클라우드 **Server**(VPC) 1대 | 해커톤 규모에 충분. 스테이징 겸 시연 서버 |
| HTTPS | 도메인 + Nginx·certbot, 또는 **Load Balancer + Certificate Manager** | 필수. 휴대폰 브라우저는 HTTPS가 아니면 클립보드 복사가 막힌다 |
| 저장소 | **Cloud DB for Cache** (구 Cloud DB for Redis) | 7일·30일 자동 삭제를 키 TTL로 처리 |
| AI | **CLOVA Studio HCX-007** 구조화 출력 | 사건 JSON 강제, 국내 서비스 |
| 암호화 | 서버 키로 AES-GCM, 키는 **Secret Manager**(해커톤에서는 서버 환경 변수도 가능) | 원문 계열 키 암호화 |
| 이미지 | GitHub Actions 빌드 → **Container Registry** → 서버에서 받아 재시작 | `main` 자동 배포 |
| 테스트 | Vitest 단위 테스트 + 평가 실행기 스크립트 | 계산·파서 회귀, 100건 평가 |

### 인프라 구성

```
[휴대폰] ─HTTPS─▶ Nginx(또는 Load Balancer) ─▶ Next.js 컨테이너 ─┬─▶ Cloud DB for Cache (사설 서브넷)
                                                    (Server, VPC)    └─▶ CLOVA Studio API
GitHub ─ PR: ci.yml(타입 검사·린트·테스트)
       └ main: deploy.yml → Container Registry → 서버 재시작
```

- **ACG(방화벽):** 서버는 80·443만 공개하고 SSH는 팀원 IP만 허용한다. 캐시 DB는 서버에서만 접근한다.
- **권한:** 콘솔 전체 권한은 인프라 담당 1명. 나머지는 **Sub Account**로 필요한 것만 준다(B: CLOVA Studio, D: 서버·DB).
- **PR별 미리보기 주소는 없다.** 휴대폰 확인은 `main` 자동 배포되는 스테이징 서버에서 한다.
- **로컬 개발은 가짜 모드가 기본이다.** 캐시 DB가 사설망에 있으므로 `STORE=memory`, AI 키가 없는 사람은 `MOCK_AI=1`로 fixture를 받는다.
- CLOVA Studio 키에는 사용 한도를 걸어 둔다.

### 환경 변수

| 이름 | 값 | 누가 갖나 |
| --- | --- | --- |
| `CLOVASTUDIO_API_KEY` | CLOVA Studio 키 | 서버, B |
| `CLOVA_MODEL` | `HCX-007` | 모두 |
| `REDIS_URL` | Cloud DB for Cache 사설 주소 | 서버 |
| `ENCRYPTION_KEY` | AES-GCM 키 | 서버 |
| `MOCK_AI` | `1`이면 AI 대신 fixture 사건 | 로컬 |
| `STORE` | `redis` 또는 `memory` | 로컬은 `memory` |

저장소에는 값 없는 `.env.example`만 올린다. 실제 키는 Secret Manager나 서버에만 두고 채팅으로 공유하지 않는다.

## 8. 만드는 순서

| 단계 | 만들 것 | 끝났다고 보는 기준 | 해커톤 시연 |
| --- | --- | --- | --- |
| 1 | `calc` + `transfer` + 예시 테스트 | 부록 예시가 1원까지 일치, 검산 5개 통과 | 필수 |
| 2 | S4 정산표 + 직접 입력 항목 | AI 없이 손으로 항목을 넣어 정산표·근거 보기 | 필수 |
| 3 | 저장소, 토큰, S5 발행, S6 결과 페이지 | 결과 링크를 다른 기기에서 열어 자기 몫 확인 | 필수 |
| 4 | S2 가림 + `parse` | 부록 원문이 가린 줄로 바뀌고 금액·화자 인식 | 필수 |
| 5 | `extract` + `resolve` + S3 검토 | 붙여넣기만으로 부록 정산표가 나옴, ‘AI 추출 초안’ 표시 | 필수 |
| 6 | 질문 4종, 범위 밖 차단 | `Q-대상` 예시에서 답 전 발행 불가 | 권장 |
| 7 | 판 관리, 변동액, 이전 공유 질문 | 부록 2판 예시 일치 | 권장 |
| 8 | 자동 삭제, 모두 지우기, 로그 필터 | 삭제 후 조회 0건 | 공개 전 |
| 9 | 평가 실행기, 공개 전 점검 | 6장 합격선·공개 전 점검 측정 | 공개 전 |

1~3단계만으로도 “정산표 → 결과 링크” 흐름을 시연할 수 있다. 5단계까지 하면 발표 15번 슬라이드의 “붙여넣기부터 결과 링크 공유까지”가 완성된다.

## 9. 테스트와 평가

| 종류 | 내용 | 기준 |
| --- | --- | --- |
| 계산 단위 테스트 | 부록 예시, 나머지 0·1·2원, 분담자 1명, 0원 항목 | 1원까지 일치, 잔액 합 0 |
| 파서 테스트 | 금액 표기 20종, 카카오톡 형식 2종 | 전부 일치 |
| 가림 테스트 | 전화·계좌·연결 안 된 이름 | 전송 본문에 0건 |
| 정리기 테스트 | 정정 대상 1개/2개, 전액 환불/취소 예정/부분 환불 | 질문·차단이 기대대로 |
| 평가 실행기 | 미공개 100건(명확 40, 정정·취소 20, 모호 20, 범위 밖 20) | 문제정의서 6장 합격선 |
| 재현성 | 같은 입력 3회 실행 | 달라지는 사례 수 기록 |
| 유출 시험 | 입력·오류·공유·삭제 경로에 식별용 가짜 문구 | 서버 로그·AI 요청·결과 페이지·삭제 후 저장소에서 0건 |
| 속도 | iOS Safari·Android Chrome 실기기, 100줄 발췌문 | 검토 화면까지 10회 중 9회 15초 이내 |

AI 모델이나 프롬프트를 바꾸면 평가 실행기를 다시 돌린다.

## 11. 역할 분담 (4명 · 바이브 코딩)

각자 AI 코딩 도구로 빠르게 만들기 때문에 **기능이 아니라 모듈·폴더 기준으로 나누고, 주고받는 데이터 모양을 먼저 고정한다.**

### 역할

| 역할 | 맡는 것 | 담당 폴더 | 8장 단계 |
| --- | --- | --- | --- |
| A. 계산·정리 | 계산기, 송금안, 조건 정리기, 판 관리, 단위 테스트 | `lib/calc.ts` `transfer.ts` `resolve.ts` `version.ts` `tests/` | 1, 6·7의 로직 |
| B. AI·파서 | 금액·화자 파서, AI 추출(프롬프트·JSON 스키마), 평가 실행기 | `lib/parse.ts` `extract.ts` `eval/run.ts` | 4의 파서, 5의 추출, 9의 실행기 |
| C. 총무 화면 | S1~S5, 브라우저 가림, 질문 카드, 근거 보기 | `app/page.tsx` `app/m/` `lib/mask.ts` `components/` | 2, 4의 가림, 5·6의 화면 |
| D. 서버·결과 | 저장소·토큰·암호화·API, S6 결과 페이지, 네이버 클라우드 배포, 자동 삭제, 로그 필터, 유출 시험 | `app/api/` `app/r/` `lib/store.ts` `crypto.ts` `log.ts` `infra/` `.github/` | 3, 8 |

- A는 화면 없는 순수 함수라 “부록 예시 테스트를 통과하게”라는 지시로 AI에게 맡기기 좋고, 틀리면 1원 단위로 드러난다.
- B는 결과가 가장 불확실하므로 프롬프트를 반복 수정·평가할 시간을 따로 준다.
- C와 D는 처음에는 fixture를 가짜 데이터로 써서 서로 기다리지 않는다.

**평가용 대화는 B가 만들지 않는다.** 문제정의서 6장의 ‘개발자가 미리 보지 않은 대화’ 조건을 지키기 위해 C나 D가 100건을 만들어 `eval/hidden/`에 두고 B에게는 결과 지표만 공유한다. B는 개발용 20~30건만 쓴다.

### 진행 순서

| 순서 | 하는 일 | 참여 |
| --- | --- | --- |
| 0. 합의 | `lib/types.ts`(6장 사건·항목·질문·정산·판 타입), `tests/fixtures/garam-4.json`(부록), 5장 API 요청·응답 모양 확정. D가 저장소·Next.js 뼈대·배포 주소를 만든다. | 4명 |
| 1. 각자 개발 | A: fixture 사건 → 정산표 테스트 통과 / B: 원문 → fixture와 같은 사건 JSON / C: fixture를 가짜 응답으로 화면 완성 / D: API가 fixture를 돌려주게 해 두고 저장·토큰·결과 페이지 완성 | 각자 |
| 2. 1차 연결 | API에 계산기 연결. 직접 입력 → 정산표 → 결과 링크가 실제로 동작 (8장 1~3단계, 시연 가능 상태) | A+D |
| 3. 2차 연결 | API에 추출 연결해 “붙여넣기부터 결과 링크 공유까지” 완성. 질문 목록과 질문 카드 연결 | B+D, A+C |
| 4. 마무리 | 질문 4종, 2판, 자동 삭제. 시연 대본대로 끝까지 2~3회 리허설 | 4명 |

### 바이브 코딩 규칙

1. **자기 폴더만 고친다.** 각자 AI 지침 파일(CLAUDE.md 등)에 “담당 폴더 밖 수정 금지”를 적는다. 남의 폴더 수정이 필요하면 담당자에게 요청한다.
2. **`lib/types.ts`와 fixture는 합의 후에만 바꾼다.** 바꾸기 전에 팀 채팅에 먼저 알린다.
3. **모두의 AI에 같은 자료를 준다:** 이 구현계획서, `lib/types.ts`, fixture.
4. **작게 자주 합친다.** 테스트가 통과하는 단위로 PR을 올리고, 연결 작업은 두 명이 함께 한다.
